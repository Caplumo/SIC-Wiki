本人是第一次编纂这种大型资料，有不足的地方还请各位多多包涵。在这里我要感谢圈内的许多大佬在本资料的编纂过程中提供的支持，为本书编纂提供帮助（无论大小）的人员我已写在页首，在这里就不多做赘述。
有句话说的好：“一流的作家写不出二流的作品”，但我这个二流的玩家正在尝试整理出一流的资料。我虽是个二流玩家，但却是这个圈子里目前最有可能也是最合适编写这种大跨度资料的人之一。我现在想的是：这种类型的资料现在是空缺的，鉴于圈内当下技术混乱无章的现状，因此必须得有这么一篇资料，以统一技术的叫法，并且为想要系统性学习技术的人提供指导，内容可能不能做到尽善尽美，但起码能起到灯塔的指引作用，让想进行系统性学习的人不至于像无头苍蝇一样乱创，到处东问一点西问一点。而对于基业大成者，阅读系统性的资料想必也会有所裨益。编者在此恳求，如有看到错误或者不当的地方请带着详细的数据更正错误，编辑部将不胜感激。
编辑本资料的初衷同上文所述，是见全圈未有大体量，大范围覆盖的详尽资料/总结。因此萌生出了编纂一个涵盖各方各面的较为详尽资料的想法。而对于我自身有可能能成功编纂这样一篇资料的原因是，我本人在SFS中各个玩法所涉猎范围是较广的，且具有一定的深度与自学能力，因此我推断我在各个方面大佬的帮助下能够整合出一篇拥有详细数据，理论与实验支撑的资料。而事实也确实如此，在面对一些前沿科技与自学极难弄懂的条目时（如一体化磁推与拓展包中的地形数据），是在这方面领域的专家为我提供的模型/数据/实验支持。在这方面的编纂中，我仅是起到润滑剂与螯合剂的作用而已。
关于《万航全典》：本作的编撰主旨是以游戏为核心。在编撰初期有人提到了将现实中的公式与原理引入本作，我给出的答复与计划是这样的：这个资料我的计划是专注于游戏本身，但因为游戏中的代码世界与现实不可能相同，所以还是以游戏内为准。而现实中的公式原理，能参考运用的只要是我知道的或者是我不知道被你们所提到的，都会加进去。因此，游戏中出现与现实不符的物理现象时我将会指出，并且将现实中的公式/定理加入附表中以供对照区分。

══════主要玩法概述══════
《航天模拟器》（《SpaceFlightSimulator》）（以下简称SFS）是一款2D的航天模拟策略类游戏，其以高度自由的组装玩法而著称。其玩法人群可主要分为以下几个玩法与流派：
1：以追求高仿真度，美观性为目标的玩法被称之为仿造。其有模仿现实的物体与
   模仿/创造虚拟的物体之分。前者被称为“实物仿造”（简称“实仿”），后者被称为“虚物仿造”（简称“虚仿”），可通简称为“仿”。其玩家所组成的社区/团体被称作“仿圈”。
   这是SFS目前被选择最多的游玩方式，有着近乎无限的自由度。
2：以利用特性制造具有对造物破坏能力的物品为目标的玩法被称作“军事模拟”（简称“军”）。同理，其玩家所组成的社区/团体被称为“军圈”。
   这种玩法被认为是SFS中未开发内容最多，也是最难的玩法。
3：以仿真操作为目标的玩法及人群无特殊称呼。
   这种玩法倾向于模拟实际中的航天操作，有着一定的操作门槛。
4：以开发拓展包为目标的玩法及人群无特殊称呼。
   这种玩法是以创造拓展包为核心。其改需要具备一定的数学&物理知识。

以上：无论哪种玩法都需要具备一定的耐心，可以说想要玩好SFS，耐心是必要的。各种主流玩法之间也并非冲突对立，很多技术比如『航行技术』在前三种玩法之中是通用的。你可以选择你所想主修的方向，也可以将多种玩法相互结合以创造你心中理想的造物。正于此地，愿你找到你想走的路。

变化。游戏内可输入文本（如火箭名称）会出现字符串数量限制，因此
有可能无法在游戏内改变其字体。

■--files/Saving：
Ⅰ  /Settings：
  ①/AudioSettings.txt：
此文件存储的是全局音频设置，格式为：
{"soundVolume": 1.0,"musicVolume": 1.0}
soundVolume：音效大小，取值范围为[0,1]，改动为大于1时等效为1，
               小于0时等效为0；
musicVolume：音乐大小，取值范围为[0,1]，改动同soundVolume。
  ②/LanguageSettings.txt：
此文件存储的是全局语言设置，格式为：
{"name": "1.5.10.2汉化by暝翮","custom": true}
name：正在应用的语言包名称；
custom：语言包来源，true为本地语言包，false为预制语言包。
  ③/VideoSettings.txt：
此文件内存储的是画面设置，格式为：
{"freeOrientation": false,"fps": 144,"menuScale": 0.74999994, "menuOpacity": 1.0,"cameraShake": true,"orbitLinesCount": 3,"FXAA": true}
freeOrientation：屏幕旋转：开为true，关为false；

■零件通用：
  一个完整的零件格式如下（整蓝图格式）：
 {
  "center": 10.0,
  "parts": [
    {
      "n": "_",
      "p": {
        "x": 0.0,
        "y": 0.0
      },
      "o": {
        "x": 1.0,
        "y": 1.0,
        "z": 0
      },
      "t": "-Infinity",
      "N": {},
      "B": {},
      "T": {
        "fragment": "",
        "color_tex": "_",
        "shape_tex": "_"
      },
      "burns": {
        "angle": 0.0,
        "intensity": 0.0,
        "x": 0.0,
        "top": "",
        "bottom": ""
      }
    }
  ],
  "stages": [],
  "rotation": 0.0,
  "offset": {
    "x": 0.0,
    "y": 0.0
  },
  "interiorView": false
}

串联格式为："center": 10.0,"parts": [{part1},{part2},{part3},...],"stages": [{"stageId": 1,"partIndexes":[a,b,c,...]},{"stageId": 2,"partIndexes":[a,b,c,...]}...]"rotation": 0.0,"offset": {"x": 0.0,"y": 0.0},"interiorView": false}
其中：
◆"center":10.0：蓝图原点x轴坐标：y坐标恒为正常蓝图大小的蓝图下边界。往左为正，
 可为负数，单位：m；
◆"n":"_"：零件名称(name)：部分不同于游戏内英文显示名称；
◆"p":{"x":0.0,"y":0.0}：零件位置(place)数据：其为笛卡尔坐标系(直角坐标系)，原点为
center所确定的原点，单位：m；
◆"o": {"x": 1.0,"y": 1.0,"z": 0.0}：方向(orientation)数据：x，y分别为贴图在对应轴上的
长度倍数。对于大部分零件而言，更改仅为视觉上的缩放，但存在例外。零件在此项数值
过大时会出现不同异常。z为旋转角度，单位为度。不同的零件有着不同的旋转中心，但
都遵循一个规则：旋转中心为链接面的中点。在有多个可连接面的情况取位于最下方（零
件自身的y轴负方向）的连接面中点；
◆"t": "-Infinity"：零件当前温度（temperature）：于蓝图中更改时除NaN外无特殊影响。当零件在世界中被以蓝图形式创建时，温度数据将会重置为“-infinity”，NaN因其特殊性无法被更改，因此可用作保护零件不被再入效应损伤（仍会产生烧痕，在高于1.5.8的版本中无法忽视引擎产生的热）。被以Rockets形式加载时，温度将会正常加载此项中的数值。
◆"N":{}：零件数值参数（Numeric）：其内为该零件的物理数据，如：实际宽度、高度、含油量、分离力等，更改后不仅会影响外观，还会影响其物理性质，如：长、宽、质量、自适应阶级、分离力度等。零件在此项数值过大时会出现不同异常。此数据对于每个零件都是不同的，对于各个零件的详细分解位于后文。
◆"B":{}：零件行为参数（Behavior）：其内为该零件的行为数据，如：引擎开关/矢量开关、整流罩适应油箱、边缘分离等开关性设置。此数据对于每个零件都是不同的，对于各个零件的详细分解位于后文。
◆"T": {"fragment": "","color_tex": "_","shape_tex": "_"}：零件贴图（Texture）：此条目为油箱，整流罩，鼻锥，分级器特有条目。["fragment": ""]为整流罩与测分离器特有，其为零件分片状态。后方双引号内为空是默认状态；为1是整体，无法分离；为left是左半片；为right是右半片。["color_tex": "_"]是零件颜色，["shape_tex": "_"]是零件形状，分级器无此项。其内可选项如图2-3-1。▼图2-3-1  ※点开图片查看高清原图
